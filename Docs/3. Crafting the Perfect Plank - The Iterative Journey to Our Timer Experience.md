# Crafting the Perfect Plank: The Iterative Journey to Our Timer Experience

**By Leo Bacevicius**

## Introduction

In my previous posts, I talked about why I chose to build directly in SwiftUI without Figma, and walked through the architecture of Plank Challenge. But there's one piece I haven't explored in depth: the plank timer itself.

This is the heart of the app. The one screen that matters more than any other. When a user opens Plank Challenge, they're here for one reason—to plank. Everything else (progress tracking, social features, badges) exists to support this single moment.

Getting this experience right wasn't straightforward. It took dozens of iterations, countless "what if we tried..." moments, and a willingness to throw away ideas that looked good on paper but felt wrong in practice.

This is the story of how we crafted the plank timer experience.

## The State Machine: Defining the Journey

Before writing any animation code or picking colors, I needed to understand the user's journey through a single plank session. What states would they move through? What would they see and feel at each stage?

After much deliberation, I landed on five distinct states:

| State | Purpose | User Mindset |
|-------|---------|--------------|
| **Ready** | Preparing to start | "I'm about to do this" |
| **Countdown** | Building anticipation | "Here we go..." |
| **Active** | The plank itself | "Hold... hold... hold..." |
| **Celebration** | Acknowledging completion | "I did it!" |
| **Completed Today** | Encouraging more | "That felt good, maybe another?" |

This state machine became the backbone of everything. Every design decision, every animation, every piece of text had to serve the user's mindset in that specific moment.

## The Ready State: Protecting the Streak

The first challenge was the ready state. What should users see before they start planking?

My initial instinct was to show a lot: the timer at 00:00, instructions, maybe some motivational text. But it felt cluttered. The screen was competing with itself for attention.

Then I asked: what's the single most important thing a user needs to know right now?

The answer: **their streak is on the line.**

That insight led to a complete redesign. Instead of generic text like "Tap to start," we now show:

```
🔥 Protect your 14 day streak

      [  Tap to Plank  ]
```

This framing transforms the action from "do a plank" to "protect something valuable." It's a subtle psychological shift, but it matters. You're not just exercising—you're maintaining something you've built.

## The Countdown: Less is More

When a user taps the button, they enter a 3-second countdown. My first version had:
- A large "Get Ready!" heading
- The countdown number
- "Tap to cancel" text
- Pulsing animations

It was too much. The countdown is only 3 seconds—users don't have time to read all that. They need to get into position.

I stripped it down to essentials:

```
      Tap to cancel

          [ 3 ]
```

The countdown number speaks for itself. The only additional information is how to abort if needed. Everything else is noise.

## The Active State: Expanding Into Focus

Here's where things got interesting—and where we did the most iteration.

### The Expansion Problem

I wanted the button to expand during the active plank, creating a sense of the exercise "taking over" the screen. The user is fully committed now; the UI should reflect that.

My first implementation simply animated the button's frame from 220pt to near-full-width. It worked, but something was wrong. The button was expanding from its top-left corner, creating a jarring, off-center animation.

The fix required separating the button into layers:
- **Background layer** (the circle): Scales up using `scaleEffect`, which naturally animates from center
- **Content layer** (timer, text): Doesn't scale, maintaining readable text at the proper size

This separation was crucial. The circle grows dramatically while the content inside remains perfectly legible.

### The Vertical Shift Problem

Another issue emerged during testing: when the navigation bars hid during active planking, the button would shift vertically. The layout was recalculating based on the new safe area.

The solution was to calculate the button's position based on the full screen height, not the safe area:

```swift
let fullHeight = geometry.size.height + safeAreaTop + safeAreaBottom
let centerY = fullHeight / 2 - safeAreaTop
```

Now the button stays perfectly still regardless of what UI elements appear or disappear. It's anchored to the true center of the screen.

### Simplifying the Content

During active planking, what does the user need to see?

- How long they've been planking (the timer)
- How to stop (confirmation they can tap)
- Visual feedback that the app is tracking

We settled on:

```
      Tap to stop

      [   🏋️   ]
      [ 00:45.23 ]
      [   STOP   ]
```

The icon provides visual interest, the timer is the hero, and "STOP" reinforces the tap action. The heading above simply says "Tap to stop"—no "Great job!" or "Keep going!" because the user doesn't need cheerleading mid-plank. They need clarity.

## The Celebration: Brief and Bright

When the user taps to stop, they've earned a moment of celebration. But how long?

Too short, and it feels dismissive. Too long, and it's annoying—the user might want to do another plank immediately.

We settled on approximately 2 seconds of celebration with:
- "Well done!" heading
- A satisfying checkmark animation
- Lava bubble effects rising up the screen

The key insight: celebration should feel earned but not interrupt the flow. It's a beat, not a pause.

## Completed Today: The Hidden Complexity

This state revealed an edge case I hadn't initially considered: **what if someone wants to do multiple planks?**

My first design assumed one plank per day. Completed? Great, see you tomorrow. But real users don't work that way. Some people do multiple short planks throughout the day. Some want to practice. Some just enjoy planking.

This realization led to several additions:

### Multiple Plank Tracking

We now store every plank as an individual entry, not just a daily total. The button shows the most recent plank time, and previous planks appear below:

```
      🔥 14 day streak

      [     ✓     ]
      [   00:45   ]
      [ Tap to plank again ]

         00:32
         00:28
```

The previous planks fade as they get older—most recent is brightest, oldest is most subtle. This creates a natural visual hierarchy without cluttering the screen.

### The Animated Flame

A static flame icon next to "14 day streak" felt dead. The streak is alive—it should look alive.

When the streak is protected (completed today), the flame now animates:
- Gradient coloring (yellow → orange → red)
- Pulsing glow effect
- Subtle scale animation

It's a small detail, but it transforms the streak indicator from information into celebration. Your streak isn't just a number—it's a living fire you've kept burning.

### Deletion for Mistakes

What happens when someone accidentally logs a plank? Or tests the app and wants to clear their data?

We added individual plank deletion in Settings with swipe-to-delete. This might seem like a minor feature, but it's about respecting user agency. Their data, their choice.

## Content Consistency: The Table That Changed Everything

Midway through development, I realized our text was inconsistent. Different states had different tones, different amounts of information, different levels of urgency.

I created a simple table to align everything:

| State | Top Area | Button Content |
|-------|----------|----------------|
| Ready | "Protect your X day streak" | Icon + "Tap to Plank" |
| Countdown | "Tap to cancel" | Large countdown number |
| Active | "Tap to stop" | Icon + Timer + "STOP" |
| Celebration | "Well done!" | Checkmark |
| Completed | "X day streak" | ✓ + Time + "Tap to plank again" |

This table became our north star. Every text change had to fit the table. It prevented scope creep and kept the experience focused.

## Positioning: The Final Polish

Even with all the logic correct, the visual positioning needed refinement. Our text was too far from the button—it felt disconnected.

The fix was switching from VStack-based layout to absolute positioning:

```swift
// Text positioned relative to button center
instructionText
    .position(x: screenWidth / 2, y: centerY - (buttonSize / 2) - 50)

// Previous planks positioned below button
previousPlanksStack
    .position(x: screenWidth / 2, y: centerY + (buttonSize / 2) + 8)
```

Now everything orbits the button. The text sits just above it, the previous planks sit just below it. The button is the gravitational center of the entire screen.

## Lessons Learned

Building this timer taught me several things:

### 1. State Machines Clarify Everything
Defining the five states upfront saved countless hours. When someone asked "what should happen when X?", I could point to the state machine. The answer was always there.

### 2. Animation Details Matter
The difference between "expands from corner" and "expands from center" is subtle in description but obvious in experience. Users feel these details even if they can't articulate them.

### 3. Edge Cases Reveal Opportunities
"Multiple planks per day" started as an edge case and became a feature. Don't dismiss unexpected user behavior—explore it.

### 4. Reduce, Then Reduce Again
Every state started with too much content. The final versions have roughly half of what I originally designed. Less text means faster comprehension means better experience.

### 5. Position Relative to the Action
The button is the action. Everything else should be positioned relative to it, not relative to screen edges or safe areas.

## What's Next

The timer experience is solid now, but it's not finished. Some areas I'm exploring:

- **Haptic feedback refinement** — Different vibrations for different states
- **Sound design** — Audio cues that complement without annoying
- **Watch integration** — Starting planks from your wrist
- **Accessibility** — VoiceOver support for the timer

But the foundation is right. The state machine is proven. The animations feel good. The content is clear.

Most importantly: I actually want to use this app. When I open it, I feel motivated to plank. The experience serves the intention.

And that's the whole point, isn't it?
